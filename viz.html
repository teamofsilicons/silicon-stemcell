Silicon Stemcell

An autonomous manager → worker agent runtime. Glass is the cloud authority, Silicon Interface is the messaging transport, main.py is a single long-lived Python process holding an event loop, and every real unit of work is a separate LLM CLI subprocess. Read from the outside in.

Glass (cloud authority) Silicon Interface (transport) Stemcell core (this repo) Manager (persistent LLM session) Worker (ephemeral LLM subprocess)

Key invariant: a manager never does long work. It only routes. Anything that would block the contact's serialized turn is supposed to become a worker, and the manager returns immediately with a reply.

02The event loop — 7 handlers, event-driven with recovery clocks

config.EVENT_LOOP is a list of handler dicts. Each has its own interval and jitter. Native file/inbox notifications are the primary trigger; the intervals are only a recovery ceiling for platforms without a healthy watcher.

Tick mechanics

wait_for_runtime_activity(timeout) maintenance tick fence? schedule.due(now, activity) run_event_loop_tick(selected) merge → context_by_carbon dispatcher.submit()
next tick — timeout = min(next due, contact integrity, inactive-call deadline, 60s or 0.5s)
backpressure

A raised exception increments failure_count and pushes failure_not_before out by 2^n, capped at 30 s — a crash can never become a hot retry loop.

maintenance fence

While maintenance is active only check_interface, check_manager_messages, and check_workers are eligible. New roots stay durably queued.

integrity

validate_contacts_integrity() runs every 300 s + a hash-derived 0–60 s offset so fleet instances never sync up.

03Dispatcher and one manager turn

ManagerDispatcher guarantees: serialized per contact, parallel across contacts. A new message for a busy contact is coalesced into that contact's next turn; a message for another contact starts its own thread immediately. Bounded at 16 concurrent contacts.

inbound context durable MAINTENANCE.enqueue_root() admission _pending[contact] thread manager-dispatch-<id> lease + heartbeat run_all_managers() complete_roots()
on exception → retry_roots() puts the same context back, same marker, no loss

Inside run_all_managers — the tool-result loop

This is the innermost agentic cycle and the one that most defines the system's behaviour.

get_manager_prompt(carbon_id) provider streams mid-stream reply(work_continues=true) fires immediately parse_manager_output → tools[] execute_all_tools()
"Tool execution results:\n…" becomes the next prompt · max 10 iterations · exits when only do_nothing remains
exit conditions

is_only_do_nothing() → clean exit. Unparseable output → an error string is fed back as the next prompt. Rate limit → lifecycle deferred + carbon told. Timeout → 1 retry, then paused with pause_reason=infrastructure. Budget exhausted at 10 → manager.iteration_limit span, work paused.

de-duplication

Tools already executed mid-stream are hashed with json.dumps(sort_keys=True) and skipped in the batch pass, so a streamed reply is never sent twice.

04Manager tools — the complete surface

Dispatched in main.py:_execute_single_tool. The manager can emit several tools per turn; results come back as one concatenated block.

Talking

  • replySend to the current contact via Interface. work_continues:true = intermediate, fires mid-stream. Supports [file=/path] → send-file and [voice=…] → tts --room.
  • message_managerMessage another manager by carbon_id or silicon_id (never both). Does not go over the wire — it queues a local manager message. The only legal path to another contact.
  • take_backRetract/replace a sent event by request_id (system-generated) or explicit event_id + force.
  • do_nothingTerminal tool. Ends the iteration loop.

Workers

  • worker/terminaltype:new — full shell access
  • worker/writertype:new — writing skill + terminal + web
  • worker · messageResume the same worker-id session with a new instruction
  • worker · checkbackOne-shot local timer in minutes; auto-removed on completion
  • worker · statusLive status of one running worker
  • worker · stopTerminate + archive the run

Self / memory

  • advertising_memory/updateReplaces the whole team-visible snapshot. ≤100 lines / 65,536 bytes. resolve_conflict:true = CAS against latest Glass revision.
  • new_sessionFresh provider session for this contact, prompts only

Boundary rule enforced in prompt, not code: a manager may never read another manager's workers, sessions, archives, or memory. message_manager is the only cross-contact channel, and any claim attributed to a carbon must carry that carbon's verbatim message as a labeled quote.

Self-modifying tool docs

Each worker's *_WTOOLS.md is the only way that worker knows what tools it has. Workers are instructed to write new tools, learned information, and skills back into that file — so the tool surface literally grows with use. This is a write-back loop into the prompt system (see L12).

L14Retry / backoff loops (four of them)main.py · core/interface.py · core/messages.py
Event-loop failure: 2^n capped at 30 s. Inbox listener: backoff doubling to 30 s on a dead durable inbox. Manager timeout: MAX_MANAGER_TIMEOUT_RETRIES = 1 — one polite "still working" retry, then paused. Root retry: any dispatcher exception calls retry_roots(), which re-admits the identical context (idempotent markers make replay safe).

Every turn opens a run with spans (manager.iteration_limit, worker.spawned, handoff.accepted, message.ingress). Rollups are pushed to Glass, which answers diag.rollup.ack; a rejection is logged back up the same socket and retried from the local SQLite store.

07Trust levels & how a manager prompt is built

Effective trust

central Carbon → per-Silicon override → Team base → very_low. Glass is authoritative; trust_policy.json holds only the last confirmed revision.

LevelGist
very_lowUnknown. No personal info, no sensitive ops, no private-file workers, no internals. Escalate to another manager rather than the central carbon.
lowKnown but unproven.
okOrdinary working trust.
highBroad operational latitude.
very_highNear-full latitude.
ultimateCentral carbon. All workers/archives/crons, config + prompt edits, restart, new sessions, approve trust up to ultimate.
